# v0.26.0 A3 design: a read on a value that may be undefined

Scope: design for unit A3 under owner Decision 31(a). The lead wrote it on 2026-10-28 against commit 64f3e5fa. It changes no source. Fable validates it before dispatch.

Labels. "Observed" means I ran a command or read the code. "Inferred" means I reasoned from observed facts and did not run a check.

Evidence. All probes are in the session scratchpad under `a3-design/`. `base/` and `copy/` are `git archive HEAD` trees. `copy/` holds the prototype of the recommended rule; `a3-recommended-type_checker.diff` and `a3-recommended-handler_verifier.diff` are its diff (about 225 lines). `t/` holds 65 probe handlers, and `probes.txt` holds the verdict of each probe on both builds. `out/` holds `zts check --json` for every tracked `.ts` file on each build. `xbin/` is a variant build that also refuses `T | null` reads and types Dict reads (section 5, Decisions 34 and 36).

## Summary

Recommended: keep ZTS309 (`unchecked_optional_access`) as the one code, and keep it in the verifier. The type checker types an index read `T | undefined` and records, under its live narrowing, every read whose operand may be undefined. A new verifier phase turns each recorded read into one ZTS309, in every function of the file. The verifier keeps its repair plan and does not stop the later stages.

Observed blast radius of revision 0: 0 of 263 tracked `.ts` files moved. Revision 1 moved 2 files. Revision 2 moves 0 files.

### R2.1 Prototype changes

1. No shape test for a Result [G1]. Revision 1 skipped any record shaped like a Result. `q20` declares its own `R = { ok: boolean; value?: P; error?: string }`, read `r.value.age`, proved `optional_safe`, and answered 200 `{}` (lead's run). The type checker no longer tests the shape: an optional field of any record widens to `T | undefined`. The skip moved into the verifier phase. The phase skips a recorded read only when its operand is `b.value`, `b.error`, or `b.errors` (by `HandlerVerifier.resultMemberKind`), and `b` resolves to a tracked Result binding (`HandlerVerifier.resultReference` returns an ordinal). `q20` is refused now.
2. A read on `unknown` is not recorded (Decision 42(b)). The type checker skips a read whose operand type is exactly `unknown`. One exception: a match-pattern binding that the checker typed `unknown` because its arm has no record type (R1.2 step 2) is still recorded, so that fallback stays fail-closed. "Admits undefined" still answers true for `unknown`, so no narrowing installs on an `unknown` value.

Under 2, every Result field (`value`, `error`, `errors` are `unknown` on the fixed Result record) is outside the rule, so the phase skip in 1 changes no measured verdict today. It keeps the exemption tied to the Result check if the Result record gains typed fields later.

The R1.4 disclosure grows by one class: a read on a value of type `unknown` (a Result `.value`, `req.json()`, a fetch `.json()`, a `dictGet` result) is not checked. The proposed passing text lists it beside the untyped values.

### R2.2 Dict reads at run time [Decision 34]

Observed with `zttp serve` (baseline build) and plain `curl` in `a3-design/rt/` (`runtime-results.txt`):

| Dict made by | `d["a"]` | `d.a` | `dictGet(d, "a")` |
| --- | --- | --- | --- |
| `parseJson` (`d1`) | `undefined` | `undefined` | `1` |
| `dictFromEntries` (`d2`) | `undefined` | `undefined` | `1` |
| `dictSet(dictEmpty(), ...)` (`d3`) | `undefined` | `undefined` | `1` |
| `requestJson` (`d5`, `isDict` is true) | `undefined` | `undefined` | not run |
| `requestJson`, then `isDict`, then chained `dictGet` (`e3`) | | | `{"a":1,"c":2}` |

A record literal cannot be a Dict: `const d: Dict<string, number> = { a: 1 }` is ZTS200 (`d4`). `req.headers` and `req.query` are plain objects, and their member and index reads return the value (`d6`).

So on every Dict the measured runtime yields `undefined` for a member or index read. `zts check` accepts these reads today (`q30`, `q34`, `q34b`, `q35`, `q37`, `p31`, `r25`). Typing the read `V | undefined` (revision 0's 34(a)) is therefore moot for correctness: a guard on the result would always take the absent branch. The right rule is a refusal that points to `dictGet`. Variant `v34bin` records every member or index read whose operand is a Dict: it refuses all nine probes above, accepts the `dictGet` chain `e3`, and moves 0 tracked files. This also explains G3: after `isDict(f)`, `f.latitude` reads `undefined`.

Separate finding for the lead, not fixed in A3: either the runtime should answer a Dict index read with the entry, or the analyzer must refuse it. Today a handler that reads a Dict with `[]` or `.` proves its properties and answers with a silently missing value.

Decoder form [Decision 42(c)]. On a request body, `requestJson`, then `isDict`, then `dictGet` at each level, with an `isDict` guard before each nested `dictGet`, works at run time (`e3`) and contains no member read. For `req.json()` and a fetch response's `.json()` I found no runtime-correct form that passes the rule: the value is not a Dict at run time (Fable's `q31`: `isDict` is false), a member read is refused under 42(c), and `dictGet` refuses it with ZTS203 (`e1`). `parseJson` over the response text may work; I did not measure it, because the fetch probes need a network.

### R1.1 The effect of an unchecked read [F4]

Revision 0 said a read of an absent value "throws". That is wrong for this runtime. The lead ran `r01` with `zttp`: a member read of `undefined` yields `undefined`, and the handler answered 200 with body `{}`. A call on an absent value (`xs[0].trim()`) faults with NotCallable, and the request answers 500 (Fable's report; I did not run it). So an unchecked member or index read gives a silently wrong response, and an unchecked call gives a 500. Every claim of "throws" or "crash" in sections 1 to 12 reads this way. The effect of `for...of` and array spread over `undefined` in this runtime was not measured.

### R1.2 Prototype changes

1. Ternary condition kills [F1]. The ternary walks its condition inside a kill watch, as the `if` arm and `&&` do, and passes the kills to `installBranchNarrowing` for both branches. A guard whose binding the condition reassigns installs nothing. `p40`, `p40r`, and `p08` are refused now.
2. A `match` over a value that may be undefined [F2]. A scrutinee that is not a name gets its inferred type (revision 0 typed only a name, so the arms of `match (ps[0])` bound nothing). Over `T | undefined`, a `when undefined` arm sees `undefined`; every other arm sees `T`, and its record bindings take their field types from `T`. When the arm type resolves to no record, each record binding is `unknown`, so a read of it is refused. `p20`, `p42`, and `p03` read `v.age` from `v: Q | undefined` and are refused now; the baseline refused `p20` and `p42` only as not exhaustive.
3. Fail-closed "admits undefined" [F3]. The check is an exhaustive switch over every type tag. True: `t_nullable`, `t_undefined`, `t_void`, `t_unknown_type`, `t_generic_param` (every one; the prototype does not read a constraint, so `T extends P` is a false refusal until the implementer reads it), a union with a true member, an intersection whose members are all true, a `t_generic_app` that does not instantiate, and an unresolved `t_ref` other than `object`. False: every always-present tag, `t_null` (Decision 36), `t_never`, and `t_error`. `null_type_idx` (no type) answers false: that is the class in R1.4.
4. Optional fields and computed record keys [F3]. A read of an optional field `p?: P` is `P | undefined` (`p04`). A literal-key read of a record field, `w["p"]`, has the field's type (`p02`). A literal index on a union of array types is the union of their elements, plus `undefined` (`p10`).
5. The Result record [new]. The fixed Result record declares `value`, `error`, and `errors` optional with type `unknown`. Steps 3 and 4 alone refused `parsed.error.kind` after `if (!parsed.ok)`, which is the form R3b teaches, in 5 tracked files. The Result check (ZTS303) owns those three reads, so a read of a Result field keeps its declared type and is not recorded. `n31` passes.

The verifier phase is unchanged.

### R1.4 The class this rule cannot see [F3]

A read whose operand the checker cannot type is not checked. The checker gives no type to: an optional-chain result (until Decision 41), an unannotated callback parameter (until Decision 41), a read from `req.headers`, `req.query`, or `req.params` (`object`), a Dict read (until Decision 34), a string index, a member read on a Dict, a member read on an untyped value (`f.current.time` checks `f.current` but not `.time`), and any expression that `inferType` leaves untyped. For each of them `optional_safe` proves nothing. Three places must disclose it, in the same unit:

- the property guidance text in `packages/zts/src/spec_discharge.zig` (the `optional_safe` row, which also writes `x != undefined`, a form the profile refuses; it must read `!==`);
- the passing and failing text of `optional_safe` in `packages/zts/src/proof_trace.zig`;
- `docs/verification.md` section 6.

Proposed passing text: "Every read of a value whose type admits undefined is checked first. Reads of untyped values (request headers, query, and params; optional-chain results; untyped callback parameters), `null` values, and arithmetic are not checked." Proposed failing text: "A value that may be undefined is read without a check. A member read yields undefined and a call answers 500." These strings are pinned: they move `packages/tools/tests/fixtures/contract/modules_all.contract.golden.json`, `plain_ts.contract.golden.json` (`test-contract-golden`), and `tests/corpus/check/bad/optional_object_access.diag` and `unchecked_optional.diag` (`test-diagnostic-corpus`). ## 2. Mechanism

The prototype has five parts. The implementer writes them again with tests; the prototype is evidence, not the patch.

1. Index typing (Step 0 variant 1). A new `.computed_access` arm in `TypeChecker.inferType` returns the element type for an in-range integer-literal tuple index, and `addNullable(elem)` for any other array or tuple index.
2. The record. `TypeChecker.walkExpr` records a read node when the type of its operand, under the live narrowing, admits `undefined`: a `t_nullable`, a `t_undefined`, or a union with such a member. It records `.member_access` and `.computed_access` (not `.optional_chain`), the operand of an array `.spread`, the iterable of `for...of`, and the object of a member assignment target. The record is keyed by node, the same pattern as `context_types` and `packages/zts/src/type_checker.zig#TypeChecker.contextTypeOf`. The prototype check for "admits undefined" ends in `else => false`, which is the fail-open direction for a refusal rule. The implementer writes an exhaustive switch over every type tag, as `TypeChecker.typeMayBeString` does, resolves references and nominal types first, and runs `zig build test-proof-swallow`, because `type_checker.zig` is on that gate's list.
3. The verifier phase. After `checkResultUses` in `packages/zts/src/handler_verifier.zig#HandlerVerifier.verify`, a new phase reads the recorded nodes in ascending node order. It emits one ZTS309 for each node that does not already carry a ZTS309.
4. Three narrowing additions in the type checker. Without them, accepted code is refused (each probe passed on the baseline and failed on the prototype until the addition):
   - Ternary branches narrow by their condition, as `&&` and `||` already do (`n10`).
   - An assignment of a value that cannot be undefined narrows a nullable binding to its inner type (`n21`; `n20` is the documented "reassignment clears tracking" pattern). An assignment of a nullable value kills the narrowing (`r31` stays refused).
   - A declaration with a `T | undefined` annotation and a present initializer narrows to `T` (`n26`). The prototype handles only the `t_nullable` spelling. The implementer removes `undefined` from a union annotation the way `TypeChecker.resolveAbsentBinding` does for `.t_union`, so `const p: P | Q | undefined = { ... }` also narrows.
5. Decision 37 adds a fourth: a narrowing of a `const` reaches a closure that captures it.

The typing also accepts one form that the baseline refused: a `match` with a `when undefined` arm over an index read is now exhaustive (`n15`; the baseline gave ZTS205 and ZTS204).
