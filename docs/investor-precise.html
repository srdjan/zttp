Metadoor · ZTTP

Prevention, Not Alerts

Metadoor and ZTTP make unsafe software impossible to build. Every other company in this market tells you what your software already did.

Every control in this market is a receipt

Software is the only engineering discipline that ships first and watches afterward. A bridge is proved before the concrete is poured. Software is deployed, then monitored.

For forty years that was a fair trade, because a person wrote every line and another person read it. Both halves of that premise are now gone. AI writes the code, and AI agents take the action: moving money, changing records, granting access, contacting customers.

The market's answer is to watch harder. Observability, audit trails, model monitoring, output filters, red-teaming, evaluation suites. They differ in sophistication and agree on one thing: they answer the question what happened.

A record of a breach is not a control. It is a receipt.

The oldest idea in accounting, applied to software

Double-entry bookkeeping does not detect an unbalanced transaction. It makes one impossible to write down. The format carries the guarantee, so the error never exists to be caught.

ZTTP does that for software. It is a compiler and runtime for a deliberately reduced programming language. Every feature it removes buys a property that becomes decidable: no hidden exceptions, no unbounded loops, no dynamic code. The result is that a program able to leak a credential does not compile. Not flagged in review. Does not build.

Metadoor is where the rules come from. A company states its governance as structured data rather than as a policy document nobody can execute: who may approve what, which steps must precede which, which two actors must differ, what must always balance. Metadoor compiles that. ZTTP proves what can be proved, enforces at runtime what proof cannot reach, and refuses to build the rest.

The result is policy that executes, and a deployable artifact that carries its own evidence.

Three things it will not build

A response that could carry a secret. Name the sensitive fields once, and any path that would put one into a response body, a log, or an outbound request fails the build.

A request to your own cloud's credential service. A permitted hostname that quietly resolves to an internal metadata address is refused at the socket. That one mistake has produced some of the largest cloud breaches on record.

A ledger entry that does not balance. Postings commit atomically, and a group whose signed entries do not sum to zero is rejected, as is one naming an account the specification never declared. The runtime does that rejecting, so it holds even for code no proof reached.

The AI that writes this code works inside the same fence. It proposes, the compiler vetoes, it tries again. On a frozen nineteen-case benchmark every case reaches a proven result, and about six in ten clear the compiler on the model's first raw attempt.

Why you can check these claims

Every deployment carries a certificate. An independent checker, sharing no code with the compiler that produced it, rebuilds the claim from the artifact's own bytes and either accepts or refuses. The producer's word is never evidence.

The certificate also states what was not proved. Each guarantee carries the strength of its weakest link, never averaged and never rounded up, and everything taken on trust is published by name.

Nobody else in this market publishes that list, because publishing one requires having measured it. For us it is a ratchet: the list only shrinks, so progress is a number rather than a narrative.

It is also the commercial wedge. Proving a control exists today means producing a policy document and a sample log. We hand the auditor a machine-checkable artifact instead.

Why now, and where we stand

Three things arrived together. AI writes a fast-rising share of new code. Agents have begun taking actions with consequences rather than drafting text for a person to send. And regulators are shifting from asking for logs of what went wrong toward asking for controls that can be demonstrated.

Each of those makes detection-after-the-fact worse, and each makes a compiler that can say no worth more.

Where we stand, precisely. ZTTP's compiler, runtime, proof format and independent checker are built and running, and the agent loop is measured against a frozen benchmark rather than demonstrated. Metadoor's governance model, its authority and receipt machinery, and its compilation pipeline are built. The contract joining the two is specified; building it is the next step. There is no hosted product: a deployment today is a self-contained binary the customer runs.

We would rather state that plainly than let a demonstration imply more. The discipline that makes our certificates publish their own gaps is the same one that makes this company worth underwriting.
