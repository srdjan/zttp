ZTS Expert

The PI coding agent behind zttp expert. It writes ZTS under compiler authority, with live language discovery, typed workflows, and a veto before any workspace write.

01 / Identity

A compiler-native PI agent

ZTS Expert is a specialized mode of the PI coding loop. The public agent command and the compiler protocol are separate surfaces with separate jobs.

User surfacezttp expert starts the coding session.
Compiler surfacezts agent --stdin-json exposes schema-v2 metadata, checks, simulations, normalization, repairs, and proofs.
Runtime boundaryPI links into the development binary. The analyzer and production runtime do not depend on the agent.
Current defaultDeepSeek V4 Flash is the product and evaluation default. Local, Claude, OpenAI, and DeepSeek providers share the same host policy.
Expert identityA protected host prompt, project instructions, compiler bootstrap metadata, deterministic task routing, and compiler-owned verdicts.
Model roleThe model authors a proposed source edit. The host controls baselines, writes, approvals, and receipts.

02 / Proof loop

One proposal crosses the fence

The pure turn machine keeps dialogue state separate from effects. The outer loop owns tool execution, verification, retry budgets, and the final write.

  1. 01

    Load stable authority

    The host combines the protected expert core, complete project instructions, and the bounded schema-v2 compiler bootstrap.

    host / compiler
  2. 02

    Classify the task

    A deterministic router selects one of 11 named expert workflows or the unknown fallback. The selected note tells the model which compiler facts and tools matter.

    expert_workflow.zig
  3. 03

    Inspect and discover

    The model reads workspace state and asks the live compiler for profile, rules, modules, effects, or proof data. The protocol bounds pre-edit discovery to keep the turn moving.

    read-only tools
  4. 04

    Propose one edit

    apply_edit must be the only tool call in its response. Its payload is a proposal. It carries no write capability and no authoritative baseline.

    model
  5. 05

    Establish the baseline and veto

    The host resolves the path, checks containment, reads the current file, and runs the compiler veto against that exact baseline.

    host / compiler

PROVEN

The user approves the checked proposal. The host writes it, verifies affected paths, reviews the resulting patch, and emits a receipt.

VETOED

The host can apply a validated compiler repair against the original baseline or return diagnostics and repair guidance for another model draft.

03 / Authority

Effects stay at the edge

The system gives each layer one job. The model proposes. PI owns effects. The compiler owns language and proof verdicts.

  • INV-01 / NO MODEL WRITE

    The model-visible catalog excludes workspace-write tools. apply_edit creates a proposal for the host.

  • INV-02 / EXACT BASELINE

    The host reads the target after the proposal arrives. A model-supplied snapshot cannot become write authority.

  • INV-03 / MANDATORY VETO

    Every proposed edit runs through the compiler gate. Prompt text and provider choice cannot bypass it.

  • INV-04 / APPROVAL BOUNDARY

    A proven edit still waits for user approval before the host changes the workspace.

  • INV-05 / POST-APPLY CHECKS

    The host verifies affected paths and reviews the applied patch before reporting completion.

  • INV-06 / BAKED POLICY

    Tools, personas, models, and skills come from the binary. Project instructions are the only external prompt context.

Prompt
Protected core capped at 8 KiB, plus complete project instructions.
Discovery
One batched discovery response and at most three read-only calls before the first proposal.
Turn
Typed states cover model waits, verification, tool execution, user approval, and completion.
Tools
Each tool declares its effect and context policy. Generic RPC admits read and analysis effects only.
Veto
The compiler checks the draft and may supply a validated repair preview. PI applies only after the proof boundary passes.

07 / Enhancements

Recommended next work

These changes improve authoring quality without weakening the compiler boundary or adding a second language authority.

Build a risk-weighted expert corpus

Now / critical

Add cases by diagnostic family, effect boundary, proof property, and common authoring task. Include direct-return and transform probes for past fail-open classes. Generate the coverage report and fail when a critical family loses its last case.

GATEEvery security-critical rule family has a positive and adversarial case; the corpus and policy hashes remain part of every result.

Execute durable workflow intent offline

Now / critical

Add deterministic durable-store and queue adapters to the test runner. Use them to assert the five workflow cases that currently stop at compiler success. Keep the parallel-secret case veto-focused unless it gains a meaningful runtime outcome.

GATEAt least 18 of 19 current cases carry executable intent checks, with no skipped backend path and no empty filter.

Make compiler metadata the sole expertise source

Now / high

Retire the detached zts-expert skill snapshot or generate its human-readable replacement from schema-v2 metadata and registries. Generate repair counts and related tables from source instead of maintaining numbers in prose.

GATENo handwritten file claims live syntax, modules, protocol version, or repair counts outside a tested compiler-owned source.

Improve first drafts from recorded failures

Next / high

Classify the ten first-draft failures by missing fact, wrong route, bad tool order, and source-shape error. Fix each cluster with a bounded workflow hint, a compiler-owned example, or an exact typed-hole step. Keep the stable prompt small.

GATEOn the same 19-case corpus, model, and policy: at least 14 first-draft passes, 19 final passes, all intent checks green, and median round trips no higher than four.

Add verified multi-file change sets

Next / high

Let the model propose an ordered set of file edits with a host-read baseline per path. Run project and system proof against the aggregate, ask for one approval, then apply atomically. The compiler should keep validating source rather than authoring whole handlers.

GATEA failed proof or stale baseline leaves every file unchanged. A passing transaction produces one proof identity and one receipt.

Extend only provable repair intents

Next / medium

Implement planned M3 repair rows after their semantic kernels exist. Add one corpus failure and one equivalence regression for each repair. Leave M5 and behavior-changing fixes outside automatic application.

GATEEvery implemented repair validates against the original baseline, re-enters the full veto, and has a diagnostic-specific corpus case.

Shrink the static tool surface

Later / medium

Consolidate the read-only zts_expert_* wrappers behind one typed schema-v2 compiler query tool, or remove proven duplicates. Preserve a stable catalog identity so provider prefix caching does not churn between tasks.

GATEReduce schema bytes by at least 40% while the full expert corpus, routing cases, context policy tests, and cache identity checks stay green.

Qualify local models on the full bar

Later / medium

Run the current local candidate through every recorded case with no skips. Report empty responses, first-draft rate, intent results, and round trips under the same identity rules used for the hosted default.

GATENo local model becomes the product default until it completes the current corpus and meets a pre-registered quality threshold.

08 / Decisions

Keep these boundaries

Recent work removed duplicate authority and stabilized the request prefix. Future improvements should preserve those decisions unless new measurements justify a change.

  • Compiler verdicts remain mandatory

    Higher first-draft rates must come from better expertise and smaller search space. Proof rules do not bend to improve a benchmark.

  • The model remains the source author

    Typed holes and compiler examples can constrain a draft. Whole-handler forge tools would restore an authority split that the current design removed.

  • The production prefix remains stable

    Per-task dynamic tool loadouts were rejected because they destabilize request identity. Consolidate schemas and benchmark a static catalog instead.

  • Automatic repairs remain semantics-graded

    M5 and behavior-changing edits require model reasoning and user review. Compiler auto-apply stays limited to validator-backed equivalence.

  • Measurements carry exact identity

    Model, profile, policy hash, corpus hash, tool catalog, and commit belong beside each result. Cross-corpus percentages do not establish a trend.

  • Cut over instead of duplicating manuals

    Retire stale expertise artifacts once schema-v2 metadata owns their facts. Compatibility copies would create another source to maintain.
